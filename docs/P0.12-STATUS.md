# P0.12 — QEMU GICv3 and CPU bootstrap (documentary reference)

Research baseline: f889c037314581d0df9baefef87a4061be594b7a. Evidence hashes are pinned in [the current source projection](../evidence/current-status-sources.json); no binary, kernel patch, raw trace, keys or device data are included.

## Demonstrated in research QEMU

- GIC_RUNTIME_VERIFIED: the QEMU virt GICv3 controller was initialized, with an IOKit child of the original Passthru controller.
- waitForChildController() returned normally and ml_set_max_cpus(1) ran on the original XNU path.
- One real SGI1 was delivered to a registered handler and completed with EOI. The observation window was approximately 30.22 seconds without an observed interrupt storm.
- The BSD bootstrap thread entered bsd_init, but did not complete it.
- Negative controls and P0.9/P0.10/P0.11 regression records passed in the pinned handoff.

## Independent blockers

B6_IOPMGR: the CPU bootstrap thread awaits a real CPU power-management provider after setting max CPUs.

B7_PTHREAD_PROVIDER: BSD reaches the original pthread_init guard and stops with the pthread provider table absent.

## Not demonstrated

No SMP, scheduler IPI, physical GIC on the G53, XNU boot on a phone, iPadOS userland, SpringBoard or Apple security equivalence. SGI1 runtime proof does not qualify peripheral SPI delivery. The public v0.1 toolchain did not reexecute QEMU: this is pinned documentary provenance, not a runtime test performed by this release.
